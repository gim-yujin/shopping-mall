# 쇼핑몰 프로젝트 k6 부하 테스트 결과 분석 보고서 (3회 반복)

## 1) 테스트 개요

**목표**
- 대규모 트래픽 상황에서의 응답시간/처리량/오류율 안정성 확인
- 동시성 이슈가 핵심인 기능(쿠폰 선착순, 주문 생성)의 정합성(초과발급·중복발급·재고 음수 등) 징후 확인

**도구/스크립트**
- Grafana k6 기반 부하 테스트 스크립트(v4) 사용
- k6의 Threshold(통과/실패 기준)를 “테스트 성공 게이트”로 사용

**부하 모델(요약)**
- `browse`, `shopping`, `coupon_rush`, `mixed` 4개 시나리오를 각각 3회 반복
- 주로 `ramping-vus` 형태(특정 시간 동안 VU를 램프업/유지/램프다운하며 가능한 한 많은 iteration 수행)

---

## 2) 전체 요약 결론

**핵심 결론 (한 줄 요약)**
- 제공된 결과 기준으로는 모든 시나리오에서 HTTP 에러 0%, 체크 100%, Threshold 전부 PASS이며, 응답시간 p95는 대부분 10~15ms 수준으로 매우 우수합니다.
- 다만 (1) 쿠폰 러시 시나리오에서 로그인 구간 p95가 ~2초로 “꼬리 지연(tail)”이 크고, (2) 홈(/)에서 1.2~1.3초 수준의 드문 outlier(max)가 반복적으로 관측되어, “대규모 트래픽/동시성 이벤트” 대비 관점에서 꼬리 구간 원인 추적이 필요합니다.

## 4) 시나리오별 상세 분석

### 4-1) Browse 시나리오
- 전체 p95 ≈ 10ms, p99 ≈ 14ms
- `GET /`(home)에서 최대 ~1.28초 outlier가 반복 관측
- 권장: 홈 요청이 느려지는 타이밍에 서버 GC 로그, DB slow query, 캐시 miss spike, 스레드풀 대기 등을 함께 수집하여 상관관계를 분석

### 4-2) Shopping(주문) 시나리오
- `order_ok` 100%, 주문 실패 0, 재고부족 0
- 3회 평균 주문 생성 수 ≈ 2109건/회 (9분 부하 구간 기준)
- 권장: 재고 경쟁 조건을 강제로 만드는 데이터셋/시나리오 및 멀티 인스턴스 환경에서 정합성 검증

### 4-3) Coupon Rush(선착순 쿠폰) 시나리오
- 쿠폰 발급 API 자체 성능은 양호 (p95 ≈ 12.3ms)
- 동시성/정합성 관점에서 초과발급/중복발급 징후 없음
- 문제점: 로그인 구간 tail latency가 큼 (로그인 p95 ≈ 1.9~2.15초)
- 권장:
  1. 로그인 경로를 분리 계측(tag 기반 메트릭)
  2. 실제 이벤트 상황을 반영한 시나리오(사전 로그인 상태 등) 추가 검증
  3. 비밀번호 해시 비용, DB 커넥션풀, 세션 저장소 등 로그인 경로 병목 조사

### 4-4) Mixed 시나리오
- 혼합 트래픽에서도 안정성 유지 (HTTP p95 ≈ 9.5ms)
- 홈(/) max outlier 약 1.3초 관측 — Browse와 동일한 원인 가능성

## 5) 서버 캐시(Caffeine) 관찰 요약
- TOTAL hit rate: browse/mixed ~99.4%, coupon_rush 98.8~99.1%, shopping 95.7%
- 권장: `userDetails` 캐시의 실제 재사용성 검증 또는 키 설계 점검

---

## 6) 동시성 문제 관점에서의 평가 & 권장 설계
- 쿠폰 선착순 정합성 패턴:
  - DB 트랜잭션 + row-level lock (SELECT ... FOR UPDATE)
  - Redis Lua script를 통한 원자 연산
- 주문/재고 차감:
  - 의도적으로 재고 1개 상품에 주문을 몰아 초과판매(absence of oversell) 확인

---

## 7) 테스트의 한계와 다음 실험 제안
- 한계: 로컬/동일 네트워크 환경에서의 결과일 가능성 — 운영 환경에서는 달라질 수 있음
- 다음 실험 제안:
  1. 로그인 tail 원인 추적 (P0)
  2. 홈(/) 1초+ outlier 원인 추적 (P0)
  3. Soak/Long-run 테스트 (P1) — 충분한 steady-state 측정 (예: 20분+)
  4. Arrival-rate 기반 부하 (P1)
  5. 멀티 인스턴스/분산 환경에서 정합성 재검증 (P1)
